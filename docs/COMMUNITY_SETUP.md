# 账号和笔记社区部署

项目已提供真实微信云开发后端。`miniprogram/config.js` 已配置用户提供的云环境 `cloud1-d1g6k44f6d5babfd1`，数据库索引、权限、内容安全授权及云函数仍需在该环境按以下步骤完成配置和部署。正式社区服务未部署时页面会返回中文连接错误。仓库改动不会自动更新已部署的旧云函数，新增安全边界必须部署当前版本并真实验证。

`serviceMode: 'community'` 使用正式云社区；备用发布可明确设为 `local` 停止该构建的云初始化/调用并使用本机学习与演示功能。这不是远程开关，也不关闭已部署云函数或修改其他客户端。`publisherName`、`contactEmail` 需填真实运营主体和可用投诉/隐私联系信息。参赛发布与证据清单见 [RELEASE_PLAN.md](RELEASE_PLAN.md)。

无需部署即可在“我的”或登录页选择“进入本机体验”。演示支持笔记、公私范围、浏览计数、点赞收藏、资料头像和学习记录，全部保存在当前设备；演示公共列表仅在本机展示，不向其他用户发布。页面明确标记演示，退出后保留数据，切换正式账号不会迁移演示资料。演示会话只存本机模式标记，没有共用密码或云端会话；任何演示操作都不会调用 `community` 云函数，因此注册登录服务暂不可用时也能进入演示。正式注册、登录和跨设备功能仍按下文部署。

## 1. 选择云环境

在微信开发者工具中使用项目的真实 AppID 打开项目，进入“云开发”，创建或选择该小程序可访问的云环境。本实现使用传统模式的文档数据库，不使用 PostgreSQL 数据库。

修改 `miniprogram/config.js`：

```js
module.exports = {
  serviceMode: 'community',
  publisherName: '填写真实运营主体',
  contactEmail: '填写真实可用联系邮箱',
  cloudEnv: 'cloud1-d1g6k44f6d5babfd1',
  communityFunction: 'community'
};
```

空 ID 会让 `wx.cloud.init` 使用默认环境，便于在开发者工具中调试；正式发布前应填写确定的环境 ID，使云函数、数据库和头像存储使用同一环境。

## 2. 创建数据库集合并关闭客户端直读写

在云数据库中分别创建下列八个集合。不要导入演示账号或虚构公共笔记。

| 集合 | 用途 |
| --- | --- |
| `community_users` | 用户资料、加盐密码摘要、作者统计、个人点赞和收藏 ID |
| `community_identities` | 学号/手机号的唯一登录索引，ID 为规范化账号的 SHA-256 |
| `community_sessions` | 会话摘要、用户 ID、绑定的微信 OpenID 和到期时间 |
| `community_notes` | 私密/公开笔记及阅读、点赞和收藏计数 |
| `community_views` | 阅读请求幂等回执及按微信用户去重的每日阅读记录 |
| `community_rates` | 注册、登录、资料及举报等操作的限流计数 |
| `community_uploads` | 头像上传临时票据及验证通过的文件归属记录 |
| `community_reports` | 私有的公开笔记举报记录及待处置状态 |

**每个集合**都在权限设置中应用 `cloudfunctions/community/database.rules.json` 的规则：

```json
{ "read": false, "write": false }
```

以上规则文件是配置模板，需要在控制台分别应用；上传云函数不会自动应用数据库或存储规则。客户端只通过 `community` 云函数访问社区数据。云函数的服务端 SDK 拥有数据库访问权限，由代码检查会话、笔记归属及可见性。不要把公开笔记集合直接设为所有人可读，否则会绕过私密笔记权限。[腾讯云开发数据库安全规则](https://docs.cloudbase.net/database/security-rules)

给 `community_notes` **分别建立四条非唯一复合索引**。下表每一行是一个独立索引，不要把多行字段合并到同一个索引。每建完一条并保存后，重新新增下一条；同一索引中，每个字段只能出现一次。升序为 `1`，降序为 `-1`。（云控制台若提示其他查询所需索引，再按具体提示补充。）

| 建议索引名称 | 索引字段及顺序 | 用途 |
| --- | --- | --- |
| `notes_public_time` | `visibility` 升序、`updatedAt` 降序、`_id` 降序 | 公共笔记分页 |
| `notes_author_time` | `authorId` 升序、`updatedAt` 降序、`_id` 降序 | 我的笔记分页 |
| `notes_public_related_time` | `visibility` 升序、`relatedKey` 升序、`updatedAt` 降序、`_id` 降序 | 关联内容的公共笔记 |
| `notes_author_related_time` | `authorId` 升序、`relatedKey` 升序、`updatedAt` 降序、`_id` 降序 | 关联内容的个人笔记 |

如果出现 `updatedAt appears multiple times in the index key pattern`，说明当前新增索引表单合并了多条索引字段。例如 `{ visibility: 1, updatedAt: -1, _id: -1, authorId: 1, updatedAt: 1, _id: -1 }` 是错误的组合。取消这次未成功的新增，按上表逐条创建：第一条只填 `visibility / updatedAt / _id`，保存后再新增第二条 `authorId / updatedAt / _id`；两条的 `updatedAt` 都使用降序。保留数据库已有的默认 `_id` 索引，不需要删除它。

学号和手机号唯一性通过确定的索引文档 ID 加数据库事务保证，不依赖先查再插的非原子逻辑。`updatedAt` 为统一的 UTC ISO 字符串，支持时间顺序排序。搜索按标题和正文的字面文本匹配，用户输入会转义后用于正则查询；大量笔记时应迁移到专用全文搜索服务。

## 3. 正式云账号使用文字头像

当前生产服务没有接入图片媒体内容安全审核，正式账号使用用户名文字头像，云头像上传入口及生产 `prepareAvatar`/`finishAvatar` 请求同时关闭。不要通过直接调用云函数、改客户端开关或仅检查文件头绕过此限制。测试中的上传票据、文件格式/大小/归属校验保留以供未来安全接入；它们不能证明图片内容审核已实现。

本机体验账号的图片头像仅存本机，可继续使用。未来开放云图片头像前，需实际接入媒体安全、确保审核通过前不能公开读取、验收拒绝和异常路径，然后通过审查后的代码变更开放。现存云图片和旧客户端的披露范围仍需运营方检查，停止新上传不会撤回已经公开的文件。

当前存储规则同时拒绝客户端直接读取和上传，避免绕过已关闭的云头像入口。上传云函数不会自动应用存储规则，需在控制台实际保存。

在云存储“权限设置”中应用 `cloudfunctions/community/storage.rules.json`：

```json
{
  "read": false,
  "write": false
}
```

当前应用无需客户端访问云存储。如果环境还供其他功能使用，应核对已有目录权限，在合并规则中保持 `avatars/` 拒绝读写，并验证客户端直接 `uploadFile` 也被拒绝。未来图片功能上线时再按审核生命周期设计权限。[腾讯云开发存储安全规则](https://docs.cloudbase.net/storage/security-rules)

保留的上传设计先取得绑定账号、微信 OpenID、有效期 15 分钟的随机票据，上传到 `avatars/<openid>/<随机票据>.<扩展名>` 后验证文件环境、票据路径、图片头及 2 MB 大小限制；资料更新不接受外部图片链接或其他账号的文件。当前生产已关闭上传；未来仍需媒体内容安全这一完整环节才能开放。

## 4. 部署 community 云函数

在开发者工具云环境选择器中选择与 `cloudEnv` 相同的环境，右键 `cloudfunctions/community`，选择“上传并部署：云端安装依赖”。函数名称为 `community`。使用支持 Node.js 18 或以上的运行时，并在云函数控制台确认超时时间 20 秒、内存 256 MB。`config.json` 同时记录了对应配置及 `security.msgSecCheck` 权限；若开发者工具只接受权限配置，则在控制台设置超时和内存。确认 OpenAPI 权限随当前版本实际生效。

生产入口接入 `security.msgSecCheck` v2 文本检查：注册昵称、修改的昵称/标签/简介，以及公开笔记标题/正文逐段检查，只有每段收到明确通过结果才提交。检查缺失、超时、额度失败、待复核或拒绝均不能授权公开；私密笔记可继续保存。真实部署后需验证安全检查通过、拒绝和接口不可用路径，确保页面显示实际失败并保留草稿。出现“内容检查暂不可用”时排查安全接口授权、调用日志及运行环境，不可改成自动放行。

依赖锁定为官方 `wx-server-sdk@4.0.2` 并提供 `package-lock.json`。本地仅安装依赖锁文件，仓库不包含 `node_modules`。如需本地云函数调试，可在该目录执行 `npm ci --ignore-scripts`；不要把本地 `node_modules` 添加到小程序主包。

数据库事务只使用 `transaction.collection(...).doc(...).get/set/remove`，不在事务中执行集合查询。`runTransaction(callback, 5)` 让冲突自动重试；数据库启用 `throwOnNotFound: false`，缺失的文档返回空值，缺失集合和其他服务错误不会被当成空文档。[官方微信云开发 SDK API 声明](https://github.com/wechat-miniprogram/wx-server-sdk/blob/master/index.d.ts)

**上游依赖审计状态：**当前官方 SDK 的传递依赖仍包含被 `npm audit` 标记的 `axios`、`lodash.set` 和 `lodash.unset` 问题。没有强制降级 SDK 或替换不兼容依赖。社区后端只向数据库 SDK 传递固定的字段名、已验证 ID、规范化输入和受票据约束的云文件 ID；发布维护时应持续跟进官方 SDK/CloudBase 依赖修复。可在函数目录运行 `npm audit` 核对当前结果。

## 5. 验证真实跨用户使用

如果注册或登录显示“社区服务暂不可用”，先确认本环境的云函数列表存在 `community`，且已使用“上传并部署：云端安装依赖”，只部署 `quickstartFunctions` 无效。重新编译后重试，并查看开发者工具 Console 中的 `[community] request failed`：`FUNCTION_MISSING` 表示函数未部署或名称/环境不匹配，`DEPENDENCY_MISSING` 表示缺少依赖，`ENVIRONMENT_ERROR` 表示环境访问配置错误。若 `code` 为 `SERVICE_UNAVAILABLE`，到云函数 `community` 的运行日志中查看 `[community] service failed`；`COLLECTION_MISSING` 的 `collection` 指出需要创建的集合，`PERMISSION_DENIED`、`RUNTIME_ERROR` 分别用于排查权限和后端运行配置。日志只保留操作类型、错误分类、错误码、集合名称及请求 ID，不记录密码、会话令牌或笔记正文。新增云端诊断需重新部署当前 `community` 代码才能生效。

注册和登录不使用笔记列表复合索引。账号流程需要 `community_users`、`community_identities`、`community_sessions`、`community_rates` 四个集合；注册首先执行限流事务，遗漏 `community_rates` 也会使注册失败。完整功能仍需创建上文列出的全部八个集合。不要为解决后端错误开放账号集合的客户端直读写权限。

使用两个微信用户或两台设备，在同一云环境依次验证：

1. 注册需要学号、手机号、用户名和密码全部填写。学号允许 4–32 位字母或数字，统一转大写；手机号为大陆 11 位号码；密码为 8–64 位字符。
2. 分别使用学号和手机号加密码登录；用户名不能用作登录账号。账号唯一性限制覆盖学号与手机号交叉冲突，避免一个登录输入对应两个账户。
3. 用户 A 创建私密笔记，用户 B 的公共列表、关联笔记、搜索、直接详情链接、点赞和收藏入口都无法获取该笔记。
4. 用户 A 将笔记设为公开，用户 B 可以读取、点赞和收藏；统计跟随更新。用户 B 的点赞和收藏各自去重，每类最多保存 1000 条笔记。
5. 用户 A 将笔记改回私密或删除，用户 B 原来点赞/收藏的记录不再出现在列表和条数中，也不能再次读取笔记正文。
6. 修改用户名、最多 6 个个性标签（每个最多 12 字）、最多 200 字的个人简介；已经发布笔记的作者资料会显示最新值。正式账号显示用户名文字头像，字母大写；确认旧客户端请求云头像上传也被生产服务拒绝。演示图片头像只在本机保存。
7. 退出并切换账号，确认个人笔记、点赞、收藏及本机学习记录不会显示上一账号的数据。
8. 用登录用户举报可见的公开云笔记，核对私有 `community_reports` 记录；同人同日同笔记去重，私密笔记不可通过举报接口泄露。确认客户端无法直接读写举报集合。

注册的手机号/学号是用户自行填写的登录标识，本实现没有短信验证码或校方学籍核验，不应把它们视作已认证身份。

## 举报与人工运营处置

`reportNote` 仅接受公开云笔记。举报理由为 `infringement`（侵权）、`privacy`（隐私）、`content`（内容）或 `other`（其他），可附限长说明；微信内用户提交后写入受限 `community_reports`，初始状态 `pending`。举报记录含原笔记 ID 和处置所需身份引用，不向普通用户公开，不能开放集合客户端直读写。

负责人在云开发控制台查询 `status: 'pending'`，核实内容、联系投诉方并记录处理结果；紧急内容的暂停传播、撤下和后续通知需落实到真实运营流程。当前没有管理员网页、管理员删除接口或完整工单系统，提交举报并不代表内容已自动下架。不要直接删除数据库笔记造成作者/互动统计失配；应使用经过验证的受控服务端处置流程维护关联数据，或由作者通过现有公私切换/删除入口配合处理。上线前若无法落实持续处置，使用明确的本机备用版本并同步审核材料。

## 统计和重试规则

- 详情页先用 `getNote(id, { view: false })` 获取正文，渲染后且仍处于前台时调用 `recordNoteView(id, { viewKey })`。客户端适配器使用既有 `getNote` 云动作并提交 `view: true`，因此原版云函数仍可累计计数；新版本额外返回每日计数和计数结果。列表、搜索和普通数据读取不增加观看次数。
- 作者阅读自己的笔记不计数。同一微信用户在北京时间（UTC+8）同一自然日对同一笔记最多计 1 次；同一个 `viewKey` 的请求重试跨日也不会重复计数。`viewKey` 需要 8–100 位字母、数字、下划线或横线。
- `getNote(..., {view: true})` 的 `view` 字段说明本次结果：`COUNTED` 为新增，`AUTHOR` 为作者自读，`ALREADY_VIEWED_TODAY` 为今日已计，`REQUEST_REPLAY` 为同一阅读请求的重试。详情显示对应提示；正文获取失败或渲染前页面已隐藏时不提交计数。
- 笔记新增返回字段 `todayViewCount / viewDay`，作者统计新增 `getStats().stats.todayViews`。今日计数按北京时间零点归零，累计计数保留；`viewDay` 是 UTC+8 自然日的整数编号。每日字段在笔记和作者文档中保存，与累计计数、阅读回执一同事务更新；编辑、公私切换保留计数，删除笔记同时扣减累计和当天汇总。浏览不会修改笔记 `updatedAt` 或改变列表时间排序。
- 今日字段需要重新上传并部署当前 `community` 云函数，不需要新增集合、索引或导入数据。旧版客户端继续使用现有接口，旧笔记累计数保留。今日统计从新版本部署后开始记录，不回填升级前当天的浏览；下一自然日起完整统计。客户端连接旧版云函数时隐藏尚未支持的今日值。
- 统计写入失败不影响已经显示的正文，页面提供单独重试按钮，重试使用原 `viewKey`。同一页面跨日返回或下拉刷新使用新的阅读标识，可计入新一天；同日刷新不会再次提交已确认的阅读。笔记列表、详情及个人统计均可下拉刷新，从服务读取最新计数。
- 阅读回执、笔记计数及作者总观看数在同一个事务中保存；点赞/收藏的个人去重 ID、笔记计数和作者总统计也在一个事务中更新。
- 新建笔记支持可选的 `creationKey`，格式同 `viewKey`。编辑页把该标识保存在草稿中；相同账号相同标识派生同一个笔记 ID，因此超时后重试不会创建两篇笔记，也不会重复增加笔记统计。没有该参数的调用兼容原先的新建行为。
- `getStats().stats.notes/publicNotes/privateNotes/views/likes/favorites` 只统计当前账号自己的云端笔记及其互动；`likedNotes/savedNotes` 统计当前用户仍可见的点赞/收藏笔记。改私密保留作者自己的历史互动总数，删除笔记则减去该笔记对应的计数。本机手记和课程/本草收藏由本机服务单独统计。
- 会话是 32 字节随机令牌，服务端只存 SHA-256 摘要，绑定微信 OpenID，7 天到期；密码使用每用户随机盐加 Node.js scrypt 摘要，客户端不保存明文密码。
- 登录按每个微信用户每 15 分钟最多 20 次、每个登录标识每 15 分钟最多 10 次限流；注册按每个微信用户每小时最多 5 次限流。超过限制返回中文提示。
- 网络失败时退出仍会清除当前设备的会话，但服务器端撤销可能尚未完成，旧令牌仍受 OpenID 绑定和 7 天有效期限制。异步请求会检查账号版本，避免旧账号迟到的结果覆盖新账号。
- 可以定期从控制台清理 `expiresAt` 已过期的会话、限流和未完成上传票据。字段为毫秒时间戳，清理应按数值比较；不要清理阅读幂等回执，否则相同旧 `viewKey` 可能再次计数。已验证头像归属记录和仍使用中的头像文件需要保留。
